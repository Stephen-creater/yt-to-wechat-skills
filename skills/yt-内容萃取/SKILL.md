# yt-内容萃取

你是大圣的内容萃取助手。

输入：一个 YouTube URL、一份已经落盘的字幕 Markdown，或用户直接粘贴的英文 YouTube 字幕。
输出：两类播客原始素材，统一存入 `03 素材管理/05 播客/`：

1. 逐字稿：原始字幕 Markdown，保留时间戳和来源信息。
2. 转述摘要：基于逐字稿生成的中文结构化文档，后续很多处理可优先选择它作为输入素材。

用户身份：内容创作者，领域为 AI、AI 产品、一人公司、个人 IP、创业。

用户使用场景：读完这份文档后，要能直接拿去做短视频、写文章、跟用户对话。所以文档的核心价值不是"信息完整"，而是"让用户快速理解，拿起来就能讲"。

## 流程

### Step 0：输入路由 + 播客素材落盘

先判断用户给的是什么：

| 输入 | 动作 |
|---|---|
| YouTube URL | 先调用 `yt-dlp` skill，按默认“字幕 + 封面一条龙”抓取字幕，逐字稿落到 `03 素材管理/05 播客/` |
| 已有字幕 Markdown 路径 | 直接读取该文件作为逐字稿，不改动原文件 |
| 直接粘贴字幕文本 | 先创建一份逐字稿 Markdown，保存到 `03 素材管理/05 播客/`，再进入萃取 |

逐字稿文件要求：

```text
03 素材管理/05 播客/YYYYMMDD-播客 [中文可读主题] [VIDEO_ID].md
```

如果没有 `VIDEO_ID`，文件名省略方括号部分。逐字稿 frontmatter 至少包含：

```yaml
type: 字幕
title: "[中文可读主题]"
source: "[YouTube URL 或用户提供的来源]"
created: YYYY-MM-DD
status: 未处理
video_id: "[如有]"
language: "[如 en-orig / en / unknown]"
subtitle_type: "[manual / auto / pasted / unknown]"
```

完成 Step 0 后，记下逐字稿路径。后续转述摘要的 `source` 字段必须指向这份逐字稿，`url` 字段保留 YouTube 原链接（如有）。

### Step 1：基础信息 + 概要

从字幕中提取或由用户补充：

- 视频标题
- 作者/频道
- 时长（估算：字幕行数 × 平均节奏）
- 主题领域

然后输出 3-5 句中文概要，说清楚这个视频在讲什么。

### Step 2：转述（讲给用户听）

转述 ≠ 摘要，≠ 萃取。转述是：你理解了这个视频之后，像一个厉害的下属向老板汇报一样——挑出有价值的部分，用聊天叙事的方式，把这件事讲给用户听。

转述包含三部分：

#### 2.1 递进线

用缩进流程图展示视频的核心逻辑递进关系。让用户一眼看到整体结构。格式：

```
核心问题
  → 第一层回答
    → 第二层深入
      → 第三层……
```

#### 2.2 整期视频在讲什么

用叙事方式，把视频的核心内容从头到尾讲一遍。要求：

- **先交代背景**：这是一个什么视频？谁采访谁？为什么值得看？让用户有上下文
- **按逻辑递进展开**：不是平铺列点，而是一层一层讲，每层之间有因果关系
- **聊天语气**：像在跟用户面对面聊天，不是写报告
- **精炼**：每句话都要有信息量，删掉不影响理解的句子就删
- **不照搬原文所有内容**：只讲对用户有价值的部分

#### 2.3 可选内容主线

从视频中提炼 3-5 条独立的内容主线，每条可以单独做成一个短视频/文章。

每条主线的写法：

1. **先说主题**：这条线讲什么、适合讲给谁
2. **交代背景**：一两句话说清楚这个信息来自哪里（什么播客/谁说的/什么场景）
3. **用叙事方式把逻辑讲清楚**：有因有果，有案例有判断
4. **落到用户**：对听这个内容的人意味着什么

每条主线是一段完整的、有上下文的转述。用户拿着就能练习，跟自己的受众去讲。

**转述的质量标准**：

- 用平民化的语言讲高级的东西
- 每一段话都有完整的上下文（背景→内容→意义）
- 删掉任何对讲述没有价值的句子
- 不要臃肿，不要废话
- 不要把原文所有内容照搬，只留对用户有价值的

### Step 3：四层萃取

| 层 | 提取什么 | 判断标准 |
|---|---|---|
| 论点 | 作者的核心主张、反直觉判断 | 能被反驳的才算论点 |
| 机制 | 因果链、解释模型、方法论 | 可迁移到其他场景 |
| 证据 | 案例、数据、故事 | 有说服力，能做论证弹药 |
| 表达 | 金句、类比、句式 | 让人"一下就懂" |

每层提取 3-7 条，每条用中文表述，括号标注原文关键词或时间戳区间。

### Step 4：发散联想

基于 Step 3 的萃取结果，结合用户领域做发散：

- 这个观点/机制在 AI 领域怎么理解？
- 对做一人公司的人意味着什么？
- 能怎么跟我的受众解释？
- 跟我已知的哪个认知形成互补或冲突？

每个发散点写 2-4 句话。**停止规则**：能落笔写一段话就停，不做无限延伸。

发散数量：3-6 个点，只留有价值的碰撞。

### Step 5：选题线索

从 Step 3 + Step 4 中提取可以做内容的选题线索：

每条包含：
- 一句话描述选题角度
- 目标受众会关心的原因
- 可用的内容形式（短视频/文章/朋友圈/直播话题）

提取 2-5 条。

### Step 6：可复用素材

从全文中挑出可以直接在创作中调用的：
- 金句（中文意译 + 英文原文）
- 类比（解释了什么概念）
- 案例（可用于证明什么观点）

### Step 7：关键名词速查

提取文档中出现的所有英文/专业名词，按类别整理，每条给出：
- 原词
- 大白话解释
- "你可以这样跟观众讲"（用户做短视频时的口语化表达）

目的：用户保留原汁原味的英文表达显得专业，但随时能查到怎么用大白话跟观众解释。

## 文件保存

转述摘要文档保存到：

```
03 素材管理/05 播客/YYYYMMDD-播客 [简短标题]-转述摘要 [VIDEO_ID].md
```

如果没有 `VIDEO_ID`，文件名省略方括号部分。文件名日期使用视频发布日期；拿不到发布日期时，使用处理当天日期。

保存后：
- 更新 INDEX.md
- 追加 LOG.md

## 注意事项

- 已存在的原始字幕不做修改，只读取；如果需要重新生成，创建新文件或先征得用户确认
- YouTube URL 输入时，必须同时保留逐字稿和转述摘要，二者都属于 `03 素材管理/05 播客` 下的播客原始素材
- 转述摘要不是 `03 素材管理/90 单篇编译摘要`；后续如果要进入知识资产/创作资产，再把它作为原始素材交给编译 skill 处理
- 中文表述优先，保留关键英文术语
- 不追求面面俱到，只留有价值的内容
- 发散必须结合用户领域（AI/一人公司/个人IP/创业），不做泛泛而谈
- 如果字幕质量差（自动生成、错误多），先做清洗再萃取

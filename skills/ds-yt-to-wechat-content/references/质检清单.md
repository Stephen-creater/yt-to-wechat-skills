# 质检清单

终稿前按本清单检查。发现问题直接改，不要只记录。

## 一票否决

- 开头第一句是“我最近听了一期播客”。
- 前 5 秒没有钩子。
- 开头为了抓人而恐吓、夸大后果，或暗示“再不做就完了”。
- 全文只是播客摘要，没有大圣自己的判断。
- 讲了 5 个以上主线，变成信息大杂烩。
- 使用“炸裂、颠覆、普通人再不学就晚了、必看、封神”等廉价刺激词。
- 用焦虑推动行动。
- 公众号标题不是一句顺口、完整、自然的人话，读起来像半截句。
- 公众号标题用“替代 / 危机 / 末日 / 不学就晚了”等焦虑表达逼迫点击。
- 封面标题太长、太抽象、不可视化，无法直接交给 `ds-cover-image`。
- 封面标题只是从公众号标题里截出来的几个字，或只是概念标签，不是一句完整可读的话。
- 承诺结果，比如“照着做就能赚钱/涨粉/转型成功”。
- 结尾是“希望对你有帮助”。
- 正文用自问自答推进，比如连续写“是什么 / 为什么 / 能不能 / 有没有 / 是不是 / 怎么”加问号，再由作者自己回答。
- 保留了删掉也不影响理解的铺垫句、过渡句、解释句。
- 正文发布区大量段落以 `。` 结尾，或者连续出现多个可以合并的小短句。
- 主体章节没有按顺序写成 `## 一、...` / `## 二、...` / `## 三、...`，或仍用裸的 `01 / 02 / 03`。
- D 版二审后，开头从读者问题 / 认知冲突变成作者感受 / 素材背景介绍。

## 主线检查

- 能否一句话说清这篇文章讲什么？
- 这条主线是否服务 AI / 一人公司 / 内容创作 / 普通人行动？
- 播客信息是否低于 40%，大圣判断和转译是否高于 40%？
- 是否删掉了和主线无关的技术细节？
- 是否留下了足够证据，避免变成空观点？
- 如果正文编号模块超过 4 个且各模块对应不同播客主线，或使用了转述摘要里的 4 条以上可选主线，默认判为主线过满，必须删并。

## 开头检查

- 不看标题，读者能否知道这篇文章要讲什么？
- 第一段有没有认知冲突、具体反差或悬念？
- 是否先抓人，再交代播客来源和人物背景？
- 有没有直接把答案说完，导致观众没有继续看的理由？
- 可信度是否自然出现，而不是自我介绍式堆身份？
- 是否先生成过 3 个开头候选，并选择了最抓人的一个？
- 第一段是否避开“我听完 / 这期播客 / 某某说 / 在某某节目里”这类素材介绍式开场？
- H1 后前 3-5 个自然段是否保留了开头保护区的抓人效果？
- 如果二审后开头不如初稿，是否恢复初稿开头，或做“初稿开头 + 二审正文”的融合？
- 开头是否只是制造认知张力，而不是制造焦虑？
- 开头有没有把复杂趋势夸成命运审判？

## 人话检查

- 每个英文术语是否满足：原词 + 人话解释 + 观众场景？
- `PR`、`session`、`agent`、`Scaling Laws`、`Amdahl's Law` 这类开发者术语，第一次出现必须解释；不能自然解释就换成人话。
- 有没有一句话超过 45 个汉字还不断句？
- 有没有为了短句而短句？同一层意思不要拆成很多孤立小段，比如“工具会变 / 模型会升级”要合并成“工具会变，模型会升级”。
- 正文发布区普通陈述段落末尾是否去掉句号？不要让文章读起来像逐句提词器。
- 有没有“机制、范式、底层逻辑、赋能、抓手、闭环”这类词连续堆叠？
- 抽象判断后面有没有立刻跟具体例子？
- 同类例子是否超过 3 个？超过就收束成“某个行业 / 某类客户 / 某个业务环节”，避免口播变成念清单。
- 有没有“这句话不是我说的，是……”这类绕路表达？直接改成“这是……讲的”。
- 读出来是否像镜头前说话，而不是文章段落？

## 冗余句检查

- 逐段问一句：删掉这句话，观众是否仍然能听懂主线？如果能，删掉。
- “但我反而不是这个感受”“我更想把它讲成另一个问题”这类转身句，如果不增加信息，直接删除或改成判断句。
- 连续 3 句以上都是“懂不懂 / 能不能 / 有没有”式追问，改成一个短判断或动作清单。
- 例子不是越多越好。口播里同类行业、同类岗位、同类业务场景最多 2-3 个。

## D 版二审检查

- 是否把 Humanizer 类规则当成二审检查层，而不是全文改写风格？
- 是否从初稿母本出发，而不是从 B/C 式碎句稿继续修？
- 是否减少了机械的“不是……而是……”“真正……”“本质上”“关键是”“重要的是”，但没有削弱清晰判断？
- 是否合并了同层意思，避免连续孤立小短句？
- 是否避免机械三段式、排比清单和“金句堆叠”？
- 是否保留了强判断、标题打开欲、章节推进和可剪金句？
- 是否保留了大圣底座：做老板不做网红、不承诺结果、手动跑通再自动化、AI 放大系统、反焦虑？
- 二审后读感是否更自然，但没有变松、变散、变随笔？
- 开头、标题和结尾是否都没有被“去 AI 味”削弱？
- 开头保护是否同时通过反焦虑检查：抓人，但不恐吓、不夸大、不逼迫？

## 承接检查

- 相邻两句话、两段话之间，必须能说清关系：因果、递进、转折、举例、收束、行动推进。
- 如果上一句讲播客观点，下一句直接跳到个人行动，中间缺少“人话解释 / 国内场景”，就是跳跃过大。
- 如果上一段讲趋势，下一段直接给方法，中间缺少“这和观众有什么关系”，就是跳跃过大。
- 修跳跃时只补最短必要桥句，比如“这件事放到普通人身上，关键变化是……”。桥句补完仍不改变理解，就删掉。
- 最终标准：删掉废话后仍不断裂；合并碎句后仍有呼吸感；补上承接后仍不啰嗦。

## 完整上下文检查

- 第一次出现人物/公司/节目时，是否交代“谁、在哪、为什么值得听”？
- 每个钉子是否有“播客观点 → 人话解释 → 国内场景 → 行动意义”？
- 段落之间是否有因果推进，而不是并列罗列？
- 观众没听过这期播客，也能不能听懂？

## 大圣味检查

- 是否体现“做老板不做网红”？
- 是否体现“完成比完美重要”？
- 是否体现“手动跑通再自动化”？
- 是否体现“AI 是新材料，不是更聪明的助手”？
- 是否体现“内容是写作系统和商业飞轮的一部分”？
- 是否有“我听完最大的感受是……”这类个人判断？
- 是否避免把大圣写成科技媒体编辑或知识搬运工？

## 反焦虑检查

- 有没有把变化说清楚，而不是把变化说吓人？
- 有没有指出普通人可控的行动？
- 有没有承认风险，但不把风险夸成命运审判？
- 有没有把“替代焦虑”转成“能力迁移”？
- 标题是否也通过本检查：可以用大众语言讲高维 / 高风险判断，但不能用焦虑制造点击。

## 标题与封面标题检查

- 公众号标题是否优先尝试了“外部强信号 + 大圣转身判断”？如果没有，是否因为素材缺少足够强的外部信号。
- 公众号标题是否同时具备具体锚点、读者关系或使用场景、明确判断？
- 外部强信号是否只是证据，而不是炫耀身份或堆名词？
- 后半句是否是大圣判断，把标题从科技新闻、产品新闻或暴富叙事拉回普通人的理解和行动？
- 公众号标题是否顺口？必须朗读一遍，不能像半截句、病句或硬塞关键词。
- 公众号标题是否完整？“听完某人”后面必须接“访谈 / 分享 / 这句话 / 这期播客”等对象，或改成“某人说……”。
- 公众号标题是否有大圣自己的判断，而不是只搬运播客人物原话？
- 公众号标题是否避免焦虑驱动？有变化、有风险可以讲，但必须落到可理解、可行动的判断。
- 封面标题是否写入 frontmatter 的 `cover_title`？
- 封面标题是否从文章内容独立提取，而不是从公众号标题里机械截断？
- 封面标题是否 8-18 个中文字符优先，中英混排不超过 22 个显示字符？
- 封面标题是否是一句完整、可读、有含义的话，而不是“代码像短信”“一人公司杠杆”这类概念标签？
- 封面标题是否保留一个核心判断、动作或情绪，能被 `ds-cover-image` 画出来？

## 公众号节奏检查

参考结构：

```text
开头：钩子 + 来源 + 大圣判断
主体：3-6 个 `##` 主章节，每个标题都提示本节判断；每个钉子都要有播客观点、人话解释、国内场景
收束：把三个钉子合成一个判断
结尾：给一个普通人能执行的最小行动
```

检查：

- 是否用 `## 一、...` / `## 二、...` / `## 三、...` 作为正文主章节标题，而不是裸写 `01 / 02 / 03`。
- `##` 标题是否有信息量，能让读者一眼知道这一节在讲什么。
- 是否没有在 Markdown 里手写 HTML 居中；居中样式交给发布主题处理。
- `###` 是否只用于章节内部小标题，而不是主章节。
- 每个钉子是否都服务同一个主线？
- 是否有某个钉子明显拖太长，像在复述播客？
- 是否有连续 300 字以上只在解释概念，没有例子或行动意义？
- 是否可以剪出 3-5 条独立金句？

## 最终交付检查

- frontmatter 是否有 `source`。
- frontmatter 是否有 `digest`，且作为公众号转发语不超过 120 字。
- frontmatter 是否有 `cover_title`，且不是公众号标题的机械截短。
- frontmatter 是否有 `youtube_body_image`，且没有把 YouTube 封面写入 `cover` / `cover_image` / `coverImage` / `image`。
- frontmatter 是否有 `cover_fallback: false`，避免正文第一张 YouTube 图被发布脚本当公众号封面图。
- H1 标题后是否有 YouTube 封面图作为正文开头配图。
- 正文发布区是否干净：没有 `文章定位`、`质检记录`、`发布备注` 等内部标题。
- 内部信息是否全部放在末尾 `<!-- wechat:ignore:start -->` 和 `<!-- wechat:ignore:end -->` 之间。
- 文件是否保存到 `01 内容创作/公众号`。
- 文件名日期是否使用 `YYYYMMDD`，例如 `20260522`。
- `质检记录` 不能只写通过项，必须写清楚删掉了哪些播客信息，或者仍有什么风险点。
- `质检记录` 是否包含开头保护、D 版二审、公众号标题与封面标题的检查结论。
- `INDEX.md` 是否更新。
- `LOG.md` 是否追加。
- 是否未修改 `03 素材管理/01-11` 已有原始素材。
- 是否未写入 `02 选题管理`。
- 是否未写入 `08 一人公司学员画像`。

# 标题与封面标题

## 调研边界

## 卡兹克标题的核心范式

不是“标题党”，而是“具体对象 + 亲历感 + 强判断 + 一点时代情绪”。

常见结构：

1. 实测 / 体验 / 用了 X 天 + 具体产品 + 个人结论。
2. 产品发布 / 新功能上线 / 新模型开源 + 一个带态度的判断。
3. 具体技术事实 + 生活化隐喻，例如沼泽、战争、消亡、成年人、打工人。
4. 小入口 + 大变化：从一个功能、模型、工具，推到行业秩序或普通人的使用方式。
5. 先给事实，再在逗号后翻出判断：前半句交代发生了什么，后半句交代这件事意味着什么。

表达风格：

- 具体名词密度高：模型、产品、公司、工具、使用场景都直接进标题。
- 口语但不松散：像一个人刚试完产品后给朋友下判断。
- 常用“我 / 你们 / 这 / 居然 / 终于 / 好像 / 真的 / 才是”制造临场感。
- 情绪不是大喊，而是克制的确定感：惊讶、告别、见证、失望、兴奋都落在具体对象上。
- 标题常常是完整句，不是名词短语；读完能感到作者已经有了立场。
- 标题读起来必须顺口，像人会自然说出来的话，不要为了塞人物或产品名写成半截句。

## 迁移到大圣标题

大圣不能照抄卡兹克的语气，要学习他的标题密度。

公众号标题要承担点击打开任务，可以比封面标题长。推荐 18-34 个中文字符；如果素材本身信息密度高，可以更长，但必须读起来像一句自然的人话。

公众号标题必须有三件事：

1. 具体锚点：人物、公司、模型、播客、工具、场景，至少一个。
2. 读者关系：这件事和普通行动者、AI 使用者、一人公司、内容创作者有什么关系。
3. 明确判断：作者听完、用完、看完之后到底下了什么判断。

## 大圣标题审美：外部强信号 + 大圣转身判断

这是本 skill 生成公众号标题时的优先结构。

核心不是更刺激，而是：借一个外部强信号开场，然后把真正的判断拉回到普通人能理解、能行动的地方。

结构：

```text
外部强信号 / 大人物判断 / 新趋势 + 但 / 真正 / 重点不是 / 我关注的是 / 更贵的是 + 大圣判断
```

写法原则：

1. 权威人物是证据，不是炫耀。可以写“Claude Code 创造者的访谈”“Anthropic CEO 说”，但目的不是堆身份，而是让标题有可信锚点。
2. 标题最好有一个转身。前半句负责吸引人，后半句负责把文章从科技新闻拉回大圣的内容主线。
3. 后半句必须是大圣判断。不能停在“Claude Code 很厉害”“一人十亿美元公司很刺激”，必须落到“领域知识更贵了”“重点不是估值”。
4. 用大众语言讲高维变化。“写代码会像发短信一样简单”比“编程门槛降低”更有画面和体感。
5. 刺激点要降温。“一人十亿美元公司”可以出现，但要用“我关注的重点不是估值”把它拉回判断，而不是推向暴富幻想。
6. 词要有价值判断。优先使用“更贵了 / 重点不是 / 我更关注 / 真正值得看的是 / 表面是……实际是……”。

正例：

| 标题 | 为什么成立 |
|---|---|
| 听完 Claude Code 创造者的访谈，写代码会像发短信一样简单，但领域知识更贵了 | 有外部锚点，有大众隐喻，有转身判断，不焦虑 |
| Anthropic CEO 说一人十亿美元公司还会出现，但我关注的重点不是估值 | 有强信号，有刺激点，也主动降温到大圣判断 |
| Claude Code 创造者说写代码会变简单，真正贵的是行业判断 | 不是讲工具厉害，而是转到普通人的可迁移能力 |

常用后半句：

- 但领域知识更贵了
- 但懂行业的人更贵了
- 但我关注的重点不是估值
- 但真正值得普通人看的不是速度
- 真正贵的是行业判断
- 重点不是工具，而是你知道要解决谁的问题
- 表面是 AI 变强了，实际是人的判断被重新定价

注意：“外部强信号 + 大圣转身判断”不是固定模板。不能每篇都机械写“某某说……但……”。如果素材没有足够强的外部信号，宁可用“具体场景 + 大圣判断”。

可用句型：

- 听完 {人物/播客}，我才发现 {真正判断}
- {产品/事件} 之后，{旧判断} 可能要改写了
- 这不是 {表层变化}，而是 {真正变化}
- {AI 正在做的事}，会让 {人群/行业} 重新洗牌
- 我以前以为 {旧认识}，直到 {证据/事件}
- {具体工具} 正在把 {原本很难的事} 变成 {普通动作}
- 听完 {人物/产品创造者} 的访谈，{大众化变化}，但 {大圣判断}
- {人物/公司} 说 {刺激点}，但我关注的重点不是 {表层指标}

禁用平标题：

- 从 XX 看 YY
- XX 给普通人的启示
- XX 方法论
- 聊聊 XX
- 普通人如何抓住 XX 机会
- AI 时代的 XX 思考

## 公众号标题和封面标题的区别

公众号标题是给人点开的。它可以长一点，可以有转折，可以把具体产品、人名、播客来源和作者判断放进去。

封面标题是给图像模型和读者第一眼看的。它要相对短、可视化、能放进画面，但它仍然必须是一句完整、可读、有含义的话。

封面标题不是公众号标题的短版。它不需要从公众号标题里摘几个字，也不需要和公众号标题逐字呼应。公众号标题和封面标题都应该从文章内容里提取，只是服务不同场景。

标题可以用大众语言讲高维 / 高风险判断，但不能制造焦虑。区别在于：前者让读者看清变化和自己的可控行动，后者把变化包装成命运审判。

判断标准：

| 项目 | 公众号标题 | 封面标题 |
|---|---|---|
| 核心任务 | 让人点开 | 让图像模型抓住画面 |
| 长度 | 18-34 字优先 | 8-18 字优先 |
| 信息量 | 具体对象 + 场景 + 判断 | 从正文提取的一句完整短判断 |
| 结构 | 可以是一整句话 | 也是一句可读的话，只是更短 |
| 命名字段 | `title` | `cover_title` |
| 后续用途 | 公众号发布标题 / H1 | 传给 `ds-cover-image` |

注意：下面不是“标题压缩示例”，而是“同一篇文章里两个标题分别从内容提取”的示例。

| 公众号标题 | 封面标题 |
|---|---|
| 听完 Claude Code 创造者的访谈，写代码会像发短信一样简单，但领域知识更贵了 | 懂行业的人更贵了 |
| Anthropic CEO 说一人十亿美元公司还会出现，但我关注的重点不是估值 | 先把系统跑通 |
| AI 第一次学会了反思，这件事比新模型更重要 | 会反思的 AI 来了 |
| 用了两周豆包手机，我好像卷入了一场新与旧的战争 | 旧手机被重新定义 |
| 因为图像模型，整个互联网正在掉进信任沼泽 | 眼见不再为实 |

## 生成流程

1. 文章定稿后再起标题，不要先标题后硬套正文。
2. 先写 5 个公众号标题候选，至少覆盖 3 种结构：实测体验型、事件判断型、隐喻反差型。
3. 删除没有具体名词的候选。
4. 删除只是在概括文章主题、没有作者判断的候选。
5. 逐个朗读标题，删除不顺口、不完整、像半截句子的候选。
6. 删除靠焦虑逼迫点击的候选，把“危险 / 替代 / 变化”改成“变化是什么 / 普通人能做什么”。
7. 选出一个公众号标题后，回到正文重新提取 `cover_title`，不要从公众号标题里截词。
8. `cover_title` 必须是一句完整短判断：能单独读懂，能被画出来，不机械呼应公众号标题。

## 快速自检

- 标题里有没有具体的人、产品、模型、场景或动作。
- 标题是否优先尝试了“外部强信号 + 大圣转身判断”；如果没用，是否有明确理由。
- 标题是不是读完就知道作者站在哪边。
- 标题是不是比“XX启示”“XX方法论”更像一个真实的人刚刚下的判断。
- 标题是不是一句顺口、完整的人话，朗读时没有卡顿或半截感。
- 标题有没有把变化讲清楚，而不是用焦虑吓人。
- 封面标题是不是从文章内容独立提取，而不是公众号标题的机械截短。
- 封面标题是不是一句完整、可读、有含义的话。
- 封面标题能不能被画出来。
- 封面标题放到 16:9 封面上会不会显得太长。

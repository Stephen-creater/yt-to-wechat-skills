# 叙事框架

本文件给 `ds-yt-to-wechat-content` 选择叙事结构用。只借结构，不仿写任何在世作者的具体措辞、语气或句式。

调研依据包括：

- Nancy Duarte 的 Sparkline：用 `what is` 与 `what could be` 的反复对照制造张力。
- Story Spine：用“日常状态 → 打破平衡 → 连锁反应 → 新状态”组织故事。
- Aristotle 修辞：同时处理内容逻辑、作者可信度、观众感受、表达目的和时机。
- Heath 兄弟 `Made to Stick`：简单、意外、具体、可信、情感、故事。

参考链接：

- https://www.duarte.com/blog/move-presentation-audience-with-story-techniques-in-presentations/
- https://www.duarte.com/blog/ultimate-guide-to-contrast/

## 默认框架：高手播客转普通人行动

适用：大多数 AI / 一人公司播客。

```text
钩子：一个认知冲突 / 具体反差 / 反常识判断
来源：谁在什么播客里讲了什么，为什么值得听
大圣判断：我听完后，觉得真正和普通人有关的是哪一句
钉子 1：播客观点 → 人话解释 → 国内场景 → 普通人行动
钉子 2：播客观点 → 人话解释 → 国内场景 → 普通人行动
钉子 3：播客观点 → 人话解释 → 国内场景 → 普通人行动
收束：这期播客真正提醒我们的，不是技术细节，而是一个方向变化
最小行动：观众今天可以做的一件小事
```

关键：播客是证据，大圣判断是主线。

开头优先级：先让读者看到自己的边界、反差或代价，再交代播客来源。不要用“我听完这期播客”开头；“我听完后的判断”可以放在钩子之后，作为转身。

开头红线：钩子只能制造认知张力，不能制造焦虑。不要夸大后果，不写“再不做就完了”，不要把复杂趋势压成命运审判。

开头候选可用三种形态：

```text
边界型：真正需要提前看见的不是 A，而是 B
反差型：大家以为问题在 A，更容易把人带偏的是 B
代价型：一个东西终于做起来以后，最容易被忽略的是 B
```

## Duarte 式对照框架：现状 vs 可能

适用：播客里有明显“旧世界 / 新世界”“今天 / 未来”“普通人旧做法 / AI 时代新做法”的对比。

```text
现在大多数人怎么理解这件事
→ 但高手在播客里给了一个完全不同的视角
→ 旧做法为什么会失效
→ 新做法真正改变的是什么
→ 普通人怎么从旧做法迁移到新做法
→ 结尾给出新的行动画面
```

口播时不要一次讲完未来，要在“现在”和“可能”之间来回切：

```text
现在：大家还在把 AI 当工具
可能：高手已经把 AI 当组织结构
现在：大家还在卷提示词
可能：真正稀缺的是判断力和系统设计
```

这种来回对照能让 8-10 分钟不散。

## Story Spine 框架：打破平衡

适用：播客里有一个清晰变化，比如“写代码变成管理 Agent”“产品团队从计划驱动变成研究预览”“执行能力不再稀缺，品味变稀缺”。

```text
过去，大家默认世界是这样的。
每天，我们都按这个方式工作。
直到有一天，AI 把某个环节打穿了。
因为这个变化，第一件事变了。
因为这个变化，第二件事也变了。
直到最后，真正稀缺的东西换了。
从那以后，普通人的行动策略也要换。
```

注意：这不是写童话。口播里可以翻译成自然中文：

```text
以前我们以为……
所以大家每天都在……
但 AI 出现后，这个平衡被打破了。
第一个变化是……
第二个变化是……
最后你会发现……
```

## 费曼式解释框架：专业词变成人话

适用：主题术语密集，如 `Product Taste`、`Agentic Engineering`、`Software 3.0`、`Research Preview`、`Amdahl's Law`。

```text
先保留原词
→ 翻译过来就是一句人话
→ 给一个生活 / 工作类比
→ 放进大圣用户的场景
→ 让观众用一个反问自测自己懂没懂
```

例子结构：

```text
他讲了一个词叫 Product Taste。
翻译成人话，就是你知道什么东西该做，什么东西不该做。
AI 时代会写代码的人越来越多，但知道该做什么的人反而更稀缺。
这就像厨房里突然多了十个超级厨师，但菜单还是要你定。
所以普通人真正要练的，不是再收藏 100 个工具，而是提高自己判断需求的能力。
```

## 乐观现实主义框架：不焦虑但不粉饰

适用：主题容易引发焦虑，如岗位替代、创业窗口、AI 速度太快。

```text
先承认变化很大
→ 拆掉最吓人的误解
→ 说明真正的风险在哪里
→ 说明普通人仍然有哪几个可控动作
→ 结尾落到兴奋而不是恐慌
```

禁忌：

- 不写“再不学就晚了”。
- 不写“所有人都会被淘汰”。
- 不把复杂趋势压成一句恐吓。

推荐句式：

```text
我不想用这件事吓你。
但它确实提醒我们，接下来真正值钱的能力会换一批。
```

## 反向清单框架：先讲别做什么

适用：播客能反推出普通人的错误动作。

```text
很多人听到这个趋势，第一反应会做 A
但 A 恰好是错的
为什么错
真正应该做的是 B
给出 3 条不要做 + 3 条应该做
```

适合大圣常见主题：

- 不要没产品先搞流量。
- 不要没业务手感先自动化。
- 不要把 AI 当成更好用的搜索框。
- 不要用 AI 绕开表达训练。

## 产品发布式框架：一个变化，三个钉子

适用：播客有一个核心新观点，可以像发布一个新世界一样讲。

```text
旧世界的问题
→ 一个新变化出现
→ 它带来三个关键后果
→ 每个后果都用一个例子钉住
→ 最后浓缩成一句判断
```

这一类稿子要极简，每个钉子都要短。

## 粘性表达检查

写完后用 `Made to Stick` 的六个问题筛一遍：

```text
Simple：这条视频能不能一句话讲清？
Unexpected：有没有一个认知反差？
Concrete：有没有具体场景、人物、数字或动作？
Credible：有没有播客人物/公司/案例做证据？
Emotional：跟观众的处境有什么关系？
Stories：有没有变化线，而不是概念列表？
```

不需要六项全满，但至少要满足四项。
